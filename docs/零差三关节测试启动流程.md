# 零差三关节测试启动流程

适用于本机连接在 `can0` 上的三台 **eRob90H100T-BM-18CN** 关节。完整顺序为：

**配置并启用 can0 → 启动主站 → 检查共享内存 → 运行运动测试 → 停止测试 → 停止主站 → 关闭 can0。**

准备两个终端：**终端 A 运行主站，终端 B 运行测试和接口管理命令**。以下路径对应当前电脑，其他电脑需替换仓库路径。

## 1. 参数与准备

| 项目 | 本次配置 |
| --- | --- |
| CAN 接口 / 波特率 | `can0` / `1000000 bit/s`（1 Mbps） |
| 主站配置 | `config/erob_3axis/co.yaml` |
| 主站 Node-ID | `127` |
| 关节 Node-ID | `1、2、3`，对应 SHM 槽 `0、1、2` |
| 共享内存 ID | `2` |
| 伺服周期 | `10000 μs`（10 ms，100 Hz） |
| 工作模式 | CSP，模式值 `8` |

关节供电、CAN 接线和终端电阻应已准备好，运动范围内无干涉。本台架曾在三轴同时使能时触发欠压，测试程序已采用**逐轴使能，每轴等待 700 ms**；使能完成后，三个关节同时执行轨迹。测试时不能同时运行 ROCOS-App 或其他 SHM 输出写入程序，也不能同时运行多个测试客户端。

两个终端分别进入仓库：

```bash
cd /home/think/Documents/GitHub/rocos-co
```

首次准备工作区时，先初始化锁定子模块并安装依赖：

```bash
git submodule update --init --recursive
./scripts/install-deps-ubuntu-22.04.sh
```

首次使用、代码更新后或缺少可执行文件时，编译并检查配置：

```bash
cmake --preset debug
cmake --build --preset debug
cmake --build --preset debug --target erob_csp_bench
ctest --preset debug --output-on-failure
./build/debug/bin/rocos_co_master --check-config --config config/erob_3axis/co.yaml
```

`erob_csp_bench` 是显式构建目标，普通默认构建不会生成它。上述构建、CTest 和 `--check-config` 均不需要启用 can0，也不会使关节运动。配置检查应显示 `SHM ID 2`、`cycle 10000 us`、三个节点以及 `Input 33 B | Output 21 B`。

## 2. 配置并启用 can0（终端 B）

先检查是否已有主站或测试进程：

```bash
pgrep -a -x rocos_co_master
pgrep -a -x erob_csp_bench
```

无输出表示未找到对应进程。若有进程，先按第 5、6 节正常停止，再修改接口配置。

确认没有运行中的主站和测试程序后执行：

```bash
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 txqueuelen 1000
sudo ip link set can0 up
ip -details -statistics link show can0
```

第一条命令确保接口处于可修改波特率的状态；即使原先已经 DOWN，也可以执行。`sudo` 要求的是本机登录用户密码。

检查输出：

- 接口显示 `UP`，位速率显示 `bitrate 1000000`。
- 正常 CAN 状态通常为 `ERROR-ACTIVE`，这个名称不表示当前已经发生总线故障；结合 `berr-counter`、收发错误计数及 `bus-off` 计数判断。
- 如果提示 `Cannot find device "can0"`，先检查 USB CAN 盒连接，并用 `ip -details link show` 确认实际接口名称。

## 3. 启动主站（终端 A）

```bash
./build/debug/bin/rocos_co_master --config config/erob_3axis/co.yaml
```

保持终端 A 打开。主站会核对实际波特率和三轴身份，配置并读回 PDO、心跳，然后进入周期运行。启动完成后应看到：

```text
[Ready] ----------------------------------------
  startup target            : op
```

主站启动后初始控制字保持失能，目标位置与启动反馈对齐。`op` 表示 CANopen 网络运行状态，**不等于电机已经使能**。主站配置的持续时间为 0，会一直运行，直到收到停止信号或出现保护故障。

如果主站报错并退回命令提示符，先处理终端 A 中的错误，不要继续启动运动测试。

## 4. 检查共享内存并运行测试（终端 B）

### 4.1 检查反馈

```bash
./build/debug/bin/erob_csp_bench 2 inspect "build/inspect-$(date +%Y%m%d-%H%M%S).csv"
```

这个命令读取并记录反馈，不写入运动目标；会消费 SHM 槽 8 的周期通知，因此也要独立运行。应看到三个槽的实际位置、速度、状态字和模式，模式为 `8`，更新周期平均值约为 `10000 μs`。本次固件正常失能时状态字为 `0x0240`。

### 4.2 运行明显可见的 45° 往返

```bash
./build/debug/bin/erob_csp_bench 2 visible "build/visible-motion-$(date +%Y%m%d-%H%M%S).csv"
```

程序执行过程：

1. 以每个关节当前实际位置为起点，对齐目标位置。
2. 按 CiA402 状态顺序操作，逐轴使能，每轴等待 700 ms。
3. 三轴各执行 **起点 → 正方向 45° → 起点** 的平滑往返，每次 6 秒，连续 3 次。这里是 45° 行程，不是 ±45°。
4. 运动持续约 18 秒，规划峰值速度约 23.6°/s；包含使能、保持和失能，整轮约 22 秒。
5. 回到起点后保持，再下使能、等待抱闸接合，确认最终失能并退出。

成功时末尾显示：

```text
PASS CSP motion and disabled final state
```

此时测试客户端已退出，主站仍在终端 A 运行。想重复观察，等待上一轮结束后再次执行同一命令即可。CSV 使用时间戳命名，保存在 `build/`，记录每拍的状态、位置、速度、模式、目标和控制字。

### 4.3 可选：小幅往返

```bash
./build/debug/bin/erob_csp_bench 2 move "build/small-motion-$(date +%Y%m%d-%H%M%S).csv"
```

`move` 模式的三个关节行程分别约为 2.8°、4.2°、5.6°，执行一次 6 秒往返，适合小幅验证，肉眼可能不明显。它与 `visible` 使用相同的逐轴使能和正常失能流程。

## 5. 结束或中断运动测试（终端 B）

正常情况下，等待测试输出 `PASS` 并返回命令提示符即可。

需要提前结束时，在终端 B 按 **Ctrl+C**。客户端会尝试通过 SHM 发送 Quick stop，再发送失能命令；中断属于非正常完成，不会输出 `PASS`，也不保证回到起点。如果主站仍正常运行，可再次执行第 4.1 节的 `inspect` 核对状态。

测试报错时先查看终端 B 的错误和终端 A 的主站状态。客户端不自动复位驱动故障；不要把重复运行当成故障复位。若主站已经退出或 SHM 更新中断，应确认关节实际停稳、失能，再进行后续处理。

## 6. 正常停止主站（终端 A）

确认终端 B 的运动测试已经结束后，在终端 A 按 **Ctrl+C**。

主站会执行组停机流程，打印 `[Shutdown]` 汇总及各轴停止状态，然后退出。等待终端 A 返回命令提示符，检查有无停机未确认或故障信息。本次台架已验证的停止状态为三轴 `status 0x240`。

在终端 B 确认两个进程均已退出：

```bash
pgrep -a -x rocos_co_master
pgrep -a -x erob_csp_bench
```

两条命令均应无输出。若无法操作主站原终端，可先用上述命令查出实际 PID，再向确认属于本次主站的 PID 发送 SIGINT。例如在终端 B 输入：

```bash
read -r -p "请输入已核对的主站 PID: " master_pid
kill -INT "$master_pid"
```

随后等待主站退出并重新检查。不要复用历史测试的 PID，也不要使用 `kill -9` 代替正常停机流程。

## 7. 关闭 can0（终端 B）

确认测试程序和主站均已退出、关节已经停稳并失能后执行：

```bash
sudo ip link set can0 down
ip -details link show can0
```

应显示 `state DOWN`，CAN 状态通常为 `STOPPED`，本轮流程结束。

**不要在主站运行或关节运动时先将 can0 DOWN。** 这会中断主站与驱动的停止命令和反馈通信。下一轮重新从第 2 节启用接口开始。

## 8. 本台架已知问题与排查入口

| 现象 | 处理方向 |
| --- | --- |
| 找不到测试程序 | 显式构建 `cmake --build --preset debug --target erob_csp_bench`。 |
| SHM 连接失败、未就绪或长时间没有新周期 | 检查终端 A 主站是否已达到 `[Ready]`，配置 SHM ID 是否为 2，以及主站是否已经保护退出。 |
| `0x3220` 母线欠压 | 检查电源功率、限流和接线，保留逐轴使能。此前同时使能曾触发该错误，不通过降低欠压阈值解决。 |
| `0x8130` 心跳错误 | 检查主站是否持续运行和总线连接，排除原因后再显式复位驱动故障。测试程序没有自动复位功能。 |
| `0x730F` 多圈电池低压 | 检查多圈编码器电池及零位，断电后的多圈位置保持不能据此保证。 |
| `invalid feedback window` | 保存主站日志并停止测试。此前约 40 分钟运行后，节点 2 的 `0x282` 反馈曾触发保护停机，原因仍待定位；不要放宽保护或反复重启来掩盖问题。 |

三轴短时运动和 SHM 核对已通过，长期稳定性问题尚未解决，不能据此宣称六轴 M5 验收完成。配置与实测细节见 [三轴配置](../config/erob_3axis/co.yaml)及[三轴实物联调报告](validation/erob-3axis-2026-11-18/README.md)。
