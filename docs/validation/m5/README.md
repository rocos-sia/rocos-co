# M5 六轴台架记录

**M5 真机待验收。** M4 已验收版本为 0.0.0-rc.4（4e7b989）。0.0.0-rc.5 单独交付已通过软件验证的台架准备工作，包括停机确认、首次停机状态接收时间和抓包分析。实测时记录源码提交、二进制 SHA-256 和台架配置副本。

2026-11-12，项目负责人确认六轴 eRob 机械臂尚未就绪，当前主机也没有物理 SocketCAN 接口。M5 等待硬件就绪后从六台驱动的身份和 PDO 映射读回开始。六轴同一 SYNC 锁存、8 ms 工况下的最坏延迟和漏拍数、各轴实际停稳时间均为未测。

## 1. 台架与配置读回

登记测试日期、操作地点、控制器、内核与调度策略、CAN 适配器与时间戳来源、总线长度与终端、机械负载、独立停机装置、六轴机械参数，以及驱动侧锁存和速度信号的采集通道。保存 App 和主站的有效 YAML、URDF、PDO 字段与机械轴的绑定。M4 的 URDF、限位及 100000 count/rad 仅用于虚拟轴。台架先由现场确认失能、接线和硬件停止措施。

1. 使用 `ip -details -statistics link show dev <接口>` 记录物理 CAN 的状态、位速率和错误计数。核对 1 Mbit/s、唯一 SYNC 生产者和六个实际 Node-ID。主站不会配置主机接口速率。
2. 从项目六轴配置产生本次专用配置，先选 `master.state: preop`。运行 `rocos_co_master --check-config --config <配置>` 保存静态摘要。按现场批准的映射策略启动维护会话。启动会发送定向 NMT 并配置心跳，`pdo_policy: verify` 仅约束 PDO 映射的处理。
3. 按[设备记录表](devices.csv)逐轴保存 1018:01–04 和 100A、1005、1016:01、1017:00，以及 1400/1600、1800/1A00、1801/1A01 的完整读回。包括 COB-ID、有效位、传输类型、条数、每项索引/子索引和位宽。可选条目缺失时保留原始 abort 和固件信息。核对实际使用的停止选项和减速度设置、固件支持的心跳报警与单独失 SYNC 反应。
4. 切换 OP 试验配置后，在失能状态核对六轴位置方向、实际位置、初始目标，以及指令模式 6060 和反馈模式 6061 的 CSP 值 8。逐项对照实物机械轴与 Node-ID。预置映射或换算有差异时，保存修订配置并复跑受影响的软件验证。

## 2. 线上周期和驱动锁存

使用独立观测通道保存整场原始数据；记录时间单位、帧时间戳落点、各采集系统的时间偏移与误差、丢帧计数。使用 can-utils 时可用 `candump -L <接口>` 生成分析输入，硬件时间戳是否受设备和驱动支持须实测。主站程序记录的 send 时间表示本机提交。独立总线记录用于判定帧到线，驱动采样/锁存信号用于判定内部生效。

在安装和负载已确认的台架执行六轴 CSP。使用可在各轴辨认的目标序列，记录运行时长、负载、目标变化和试验段开始/结束的 SYNC 序号。六轴在同一 SYNC 采用各自的预期目标是功能验收条件。记录从 SYNC[k]、最后一帧反馈到齐和各轴锁存时刻三个时间点，分别计算整拍延迟和收齐后延迟。交付最坏值、漏拍数/总拍数、受影响轴、固定附加延迟和偶发跨拍。SHM v2 首轮未提供 App 六轴命令代号。

以下示例使用六轴默认映射、Node-ID 1–6、无计数器的 SYNC 和标准 11 位 CAN 帧。接口和采样区间按真实抓包填写。第 100–500 窗口需要观察到第 501 个 SYNC。

```sh
python3 scripts/analyze-bench-trace.py run.log --interface can0 --nodes 1,2,3,4,5,6 \
    --first-sync 100 --last-sync 500 --csv windows.csv > summary.json
```

工具输出每拍的 SYNC 间隔、12 帧反馈收齐耗时、最后目标帧到下一 SYNC 的余量、缺失/重复/错误 DLC 的 COB-ID 和目标提前出现情况。报告的 incomplete_windows 是抓包中不完整或无效的窗口数。完整空档、采集器丢帧和驱动错拍还需对照原始数据、时钟和驱动记录归因。末尾未闭合窗口不进入统计。表中用“未确认”标记缺乏驱动侧证据的锁存结论。

## 3. 故障与停稳

保存主站退出码。正常结束为 0，配置错误为 2，ready 前启动失败为 3，ready 后运行或停机失败为 4。

每种工况保留一份带统一 t0 标记的注入、CAN 数据、主站日志、驱动状态及独立机械速度轨迹。每轮恢复后重新核对身份、映射、位置对齐和显式使能。节点重启与节点掉线、断线与真实 bus-off 分开记录。仅消失 SYNC 的场景需要独立观测到主站心跳仍在继续。主站进程异常退出时从驱动本地或外部采集获得反应，日志中无法观测的量写“未确认”。

按[停机记录表](stops.csv)记录共同 t0、检测方 T1、各轴 T2 和 T3，所有时间差使用毫秒。T2 从约定停止状态及证据判定；主站可提供首次观测到该状态的主机单调时钟时间，其中包含反馈采样和传输延迟。T3 使用预先记录的速度阈值、持续时间和机械测量。整组 T3 取最后一轴；缺任一轴独立停稳证据时，整组写“未确认”。本轮不设停机时间上限。App 意外退出或暂停的独立监督留在本轮范围之外。

## 已完成的软件预演

0.0.0-rc.5 在隔离 vcan 上通过 28/28 项 CTest，Release 默认测试通过 8/8 项。其中，正常退出时模拟第 5 轴拒绝进入停止状态，主站报告组停机未确认；模拟外部 SYNC 生产者后，主站停止自行发送 SYNC。两个工况都运行了独立从站进程。对 M4 正常抓包的第 20–40 个窗口复跑分析，21 个窗口均收齐 12 帧反馈及 6 帧目标。对 M4 故障整段抓包复跑，发现 124 个窗口缺少 0x285；整段包含启动和停机区间。这些结果用于回归采集和判断逻辑，设备和机械实测记录仍待填写。
